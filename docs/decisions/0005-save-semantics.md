# 0005 存档真实语义与保护

- 状态：已采纳
- 日期：2026-10-31
- 决策者：项目维护者

## 背景

游戏存档是用户数据。存档后端如果只做“成功”空实现，或把测试存档与真实存档混在
一起，会造成不可逆损失，也会让玩法验收失真。

## 决定

1. 实现真实文件语义：打开、读、写、提交、大小、目录、错误码。
2. 存档根目录固定为 `ux0:data/mhgu-vita-port/savedata`。
3. 测试/试玩必须使用独立副本；运行前后 preserve/restore/verify，原始存档只读保留。
4. 自动化运行不得删除或覆盖用户原始存档；失败时优先恢复。
5. 存档日志只记录路径、大小、结果码，不打印内容/密钥。

## 后果

- 存档可跨进程读回，玩法闭环有基础。
- 需要处理半写、断电、强杀、只读介质和空间不足。
- 测试流程更繁琐，但避免用户数据损失。

## 替代方案

- **内存假存档**：无法验证跨进程/真实玩法。
- **直接使用用户存档测试**：风险高，已禁止。
- **统一成功 stub**：会掩盖未实现路径。

## 证据

- 真实存档加载/写入/跨进程读回：L3（Vita3K）。
- 真机休眠/唤醒/强杀：未验证，见 HW-08。
