# 0003 离线着色器与静态资源准备

- 状态：已采纳
- 日期：2026-10-31
- 决策者：项目维护者

## 背景

游戏使用大量 Maxwell 着色器。Vita GPU 只接受 GXP；在 Vita 上编译 Cg/Maxwell 会带来
不可接受的启动时间、内存和工具依赖，也会把复杂解析放进逐帧路径。

## 决定

1. PC 端离线完成：SPK 解析、stage 内容哈希、GLSL/IR 生成、Cg 编译、GXP 打包、
   资源 sidecar、索引。
2. Vita 端只加载固定索引/GXP/sidecar，按需创建 GXM 对象；动态 uniform、骨骼、纹理、
   RT 和同步仍由运行时管理。
3. 静态包按 stage SHA、viewport、input signature 分层标识；拒绝未知 stage，不回退到
   默认 shader。
4. 不要求静态包全量常驻；使用有界缓存和按需上传。

## 后果

- 启动与逐 draw 路径更可预测，Vita 不依赖编译器。
- 需要维护离线工具链和包身份；重建不是一键流程（见 ISSUE-08）。
- 包的完整性可以离线校验，但 GXM 链接/像素/性能仍需运行时验证。

## 替代方案

- **Vita 上编译**：工具链不可用、内存/时间不可控。
- **运行时解释 Maxwell**：性能与正确性风险高，偏离架构。

## 证据

- 静态包格式与运行时加载见 [静态着色器包](../reference/shader-package.md)。
- 当前包在 Vita3K 中实际使用；完整覆盖仍开放。
