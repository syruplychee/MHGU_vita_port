# 0009：CPU 视频表面采用原生按行读回

日期：2026-11-01。状态：实现；L1/L2 通过，L3 单次运行已命中原生读回（单平面复制约 0.06–0.43 ms，最终清点 Y/UV 均值 0.119/0.060 ms）；真机与完整回归待验证。

## 背景

旧 B123–B130 已测得片头原始内容为 29.97 FPS，解码与 VIC 合成钩子为毫秒级，
但实际内容约 2.7–2.9 FPS。持锁栈采样落在 SDK `NvRmMemReadStrided` 的按行缓存
同步路径。继续降低互斥体 Enter 成本没有明显提高内容更新率。

本次核对锁定 SDK 的原始 ARM 指令：`NvRmMemReadStrided` 在成功查到 SDK 对象后，
对每行调用内部缓存同步（SDK+0x2a1a60），再调用 memcpy。缓存同步又查询同一对象并
进入/退出 SDK 锁。视频表面是本项目 `media_video.c` 同步 CPU 写入的 NV12 数据，
不需要每行重新查询对象或等待 GPU 写回。

## 决定与边界

只替换 SDK 平台内存接口里的视频复制循环，不改游戏播放器、时钟、跳帧策略或内容。
原始 SDK 的句柄查询、失败返回、范围不足时的部分复制及未知来源的缓存同步仍保留。

- VIC 成功写好 Y/UV 表面后，登记至最多八项的元数据表：服务状态、nvmap id、CPU
  地址和有效范围。没有复制像素缓存，也没有新增 GPU 分配。
- 原生读回要求 nvmap id 仍存活、地址和范围仍被该分配覆盖。nvmap id 单调增长，
  释放后的旧记录不能匹配复用同地址的新分配。
  最后一个服务句柄关闭及解码器重建时清空对应记录，防止服务槽重用后 id 从头计数。
- 检查源/目的 span、内存权限和不重叠后，原生逐行 memcpy；两边连续时一次 memcpy。
  目的行 padding 不改变。所有检查在第一次写入前结束。
- 只对上述 CPU 已写好的表面使用快路，因此不会跳过仍由 GPU 生产的数据的同步。
  没有匹配、无效 stride、范围不足或重叠时恢复原始指令并执行原 SDK 循环。
- `media-native-readback.disable` 可在启动前关闭快路，用同一 SELF 做受控对照。
  关闭后执行原实现，不伪造复制成功。

## 二进制与 ABI 契约（L0）

绑定 `config/target-1.4.0.json` 的 SDK SHA256 `9a9b7035266637ee693a32da6b0fde54bda00e897bef05b1c8d8cda30f8ac8b0`
及 Build ID `cb8e7f9a74a4a854ff013489ecc1e8b0def23a75000000000000000000000000`。
用于反汇编的旧 `sdk.elf` 的整个 `.text` 已与该 NSO 解压 text 逐字节相同核验；
REA 能读取 ELF 身份，但当前 Windows 后端不支持 ARM ELF 反编译，指令分析来自
本机 `arm-vita-eabi-objdump -d -m armv7`，不把反汇编冒充 REA 伪代码输出。

| 项目 | 绑定 |
|---|---|
| 原函数 | SDK+0x2a1dd0，长度 0x1a4，ARM 状态 |
| 替换指令 | SDK+0x2a1ed8：`3c b0 90 e5`，即 `ldr fp,[r0,#0x3c]` |
| 审查/运行校验范围 | `[0x2a1ed8,0x2a1f74)`，156 字节 |
| 范围 SHA256 | `c7f0dc8a012c37f6d7fe334214369b09034b21fe96da90c146fe13102a0ac924` |
| 入口寄存器 | r0=SDK 对象，r1=行数，r4=目的地址，r6=源偏移，r7=每行字节 |
| 原函数栈局部 | `[sp+4]`=目的 stride，`[sp+8]`=源 stride |
| SDK 对象字段 | `+0x38`=CPU 地址，`+0x3c`=字节容量 |
| 成功后续 | SDK+0x2a1f50，原始 `add sp,#20; pop {...,pc}` 恢复调用者寄存器和 LR |
| 原路后续 | 在保存帧中重放 `fp=对象容量`，回 SDK+0x2a1edc |

`VP_HOST_BRIDGE_FUNCTION` 只负责完整保存上下文；服务 0x24a 总会明确选择原路或
原函数收尾地址，不使用桥接默认的 LR 作为中间指令返回地址。原始 r4–r11、SP、LR
由既有原函数栈恢复。源函数其余代码不重排，不改变模块布局；代码 cache 维护继续
使用既有补丁提交流程。补丁计划及生成头同时更新，任何原字节/范围 SHA 不符都拒绝。

## 测量与回滚

逐行复制纯逻辑由宿主测试覆盖边界、不同 stride、padding、溢出与失败不写入。
运行需同时记录 `DECODE_TIME`、`COMPOSITE_TIME`、`READBACK` 和实际窗口画面。
比较解码与交付计数的时间跨度及间隔分布，不以模拟器窗口 FPS 宣称内容达到 30 FPS。
测试使用独立中文存档副本并恢复原档，实际测试结果另记当前状态文档。

如出现内容错误、资源生命周期问题或没有实际收益，先用 disable marker 回到原路径；
不删除原始失败路径、不扩大到未知图形表面。真机 cache、内存与性能仍需 L4 验证。
