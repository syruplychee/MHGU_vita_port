# 0006 证据分级

- 状态：已采纳
- 日期：2026-10-31
- 决策者：项目维护者

## 背景

移植项目容易出现“编译成功就写完成”“模拟器截图就写真机通过”“单 draw 通过就写整帧
正确”。这些混淆会误导贡献者和用户。

## 决定

采用 L0–L5 证据分级：

- L0 静态审计
- L1 宿主测试
- L2 构建/链接
- L3 Vita3K
- L4 真机
- L5 用户玩法验收

规则：

1. 每个结论标注级别和范围。
2. 低级别不能冒充高级别。
3. 单次运行不写成受控加速比例；性能结论需要分布和样本。
4. 修复未实际运行验证时只写“已实现，待验证”。
5. 真机与模拟器冲突时以真机为准。

## 后果

- 文档更保守，但可审查、可复现。
- 需要维护运行目录、哈希、版本和日志。
- PR 审查可以明确指出证据缺口。

## 替代方案

- **只写结论**：无法复核，容易被单次噪声误导。
- **只写日志**：信息过载，缺少判断。
